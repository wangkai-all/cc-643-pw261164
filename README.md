# 门店商品销售榜（本地应用）

按实际销售明细计算的本地门店商品销售榜：明细分片存放，网页可录入销售 / 退货 /
历史更正，选择门店与名额（N），查看每一版榜单以及更新前后的入榜、出榜和名次
变化。**榜单不保存任何固定演示结果**，每次都由当前明细计算；发布的版本只保存
结果快照与输入范围，可随时复核。

## 运行

```bash
cd /workspace
python3 -m rankapp            # http://127.0.0.1:8765/
# 可选：--port 9000 --db var/rankapp.sqlite3
```

无需安装任何第三方依赖（Python 3.10+ 标准库）。打开页面后点“载入演示明细”即可
得到三份分片文件与第一版榜单；也可以用“导入 sample_shards 全部文件”走文件通道。

运行测试与完整流程演示：

```bash
python3 tests/test_rankapp.py          # 19 个用例：算法、幂等、原子发布、HTTP
python3 tests/test_frontend.py         # 前端冒烟：用 DOM 桩跑 app.js，校验榜单与补取过程渲染
python3 scripts/demo_flow.py           # 新增→更正→补位，逐版与全量分组排序对照
python3 scripts/fuzz2.py               # 随机明细与全量排序的交叉验证
```

前端测试需要本机有 `node`（仅用于在无浏览器环境下执行 `web/app.js`），没有时
自动跳过；它不引入任何 npm 依赖。

## 计算口径

1. 先按 `(门店, 商品)` 累计**净销售额**（销售为正、退货/更正按录入金额），再取
   每店前 N 名。数量不参与排名，只用于展示明细条数。
2. 两种取 N 规则：
   - **严格取 N**：净额降序取前 N；同额时按商品编号升序稳定打破平局。与末位
     同额但编号更大的商品会落榜，榜单上以“末位同额”标出。
   - **保留末位同额**：取净额不低于第 N 名的全部商品，绝不截断并列，条数可能
     多于 N。
3. 净额 ≤ 0 的商品不上榜（否则“保留末位同额”会在非正区间无限扩张）。
4. 某商品减少后，原先榜外的商品自动补位；删除最后一条明细时接口区分
   `absent`（商品已不存在）与 `zero`（仍有明细但净额为零）。

## 分片只汇报局部候选为什么会漏

只取每片局部前 N 会漏掉“每片都不突出、跨片相加才上榜”的商品。演示数据里
门店 A 的 `G-001` 在三个分片各排不进局部前 5，但 120+130+140=390 是全局第一：
它的局部候选完全不会出现，只有把各片净额补取并累加后才能看到。

## 跨片候选补取与停止条件

设门店在第 i 个分片的局部桶降序排列，`z_i` 为该分片的**局部第 N 大值**（桶数
不足 N 取最小桶值，无桶取 0）。没有被发现的 SKU 在每个分片都不在前 N，故每片
局部净额 ≤ `z_i`。每轮再向每个分片索取净额 ≥ t 的全部桶，并对新出现的 SKU
**按键补齐所有分片**，得到精确全局净额。于是任何仍未发现的 SKU：

```
全局净额 ≤ U(t) := Σ_i max(0, min(z_i, t − 0.01))
```

把候选集中第 N 名的净额记为 T。当 `T > U(t)`，所有未发现商品都严格低于 T，
既进不了前 N，也不可能与末位同额（同额规则要求“不低于”而非“严格大于”），
于是**停止补取**。若不满足，就把 t 下调到下一个更小的局部桶净额再补一轮；
金额精确到分、t 严格递减且来自有限集合，最后一步以 0.01 为阈值取走全部正额
桶（此后 U=0）。因此算法必然终止，结果的全局正确性由上面的不等式保证。

页面的“分片补取过程”逐店逐轮展开：各分片局部第 N 大值 `z_i`、本轮阈值 t、
上界 `U(t)`、候选第 N 名 `T`、本轮的 `T vs U` 比较、补取的桶数/明细数/新候选
数、以及每一轮的停止或继续理由；另列出分片局部前 N（含各片局部分数）与所有
跨片补取到的商品及其分片构成。

## 为什么结果一定与全量排序一致

- 补取过程本身只读分片局部桶，不读全量排序；
- 每次计算（含发布）都再用**全量分组排序**独立重算一遍，逐店逐项对照；不一致
  时页面标红并且**拒绝发布**；
- `scripts/fuzz2.py` 用 2000 组随机明细（含负额、零额、并列、空分片、多门店）
  与全量排序交叉验证，`tests/test_rankapp.py` 再固定 300 组回归。

## 批次重传与分片暂时退出

- 批次以 `(分片, 文件 SHA-256, 批次号)` 去重：完全相同的重传返回 `duplicate`，
  不重复累加；同批次号但摘要不同返回 `conflict` 并拒绝写入；行级再按
  `record_id` 去重，换批次号重传同一批数据也不会重复。
- 整批校验失败时一批都不写入；视频文件之外的解析失败不会留下半批数据。
- 分片可“暂时退出”。退出的分片会**阻断发布**（`409`），页面展示待同步分片，
  不会发布只含部分分片的榜单；恢复上线后才能发布。启用中但数据被清空的分片
  同样阻断；从未导入过明细的分片视为“未启用”，不参与也不阻断。

## 版本与输入范围

每次发布写入一个只追加的版本，保存：模式、N、门店、分片编号、各分片批次号、
逐条记录编号、记录摘要（SHA-256）、完整结果（含补取轮次与对照）以及输入范围。
页面“版本与对照”可查看每版明细、点开任意版本，并选择任意两版对照入榜、出榜
与名次/净额变化。

## 目录

```
rankapp/ranking.py   净额聚合、取 N 规则、分片补取与停止条件、全量对照
rankapp/store.py     SQLite 存储：幂等批次、明细/事件、原子发布、版本对照
rankapp/ingest.py    JSON/JSONL/CSV 明细文件解析（不改写文件）
rankapp/server.py    标准库 HTTP 服务与 JSON 接口（含 CSP、路径校验）
rankapp/seed.py      演示明细（仅明细，不含榜单结果）
web/                 单页前端（无框架、无外链资源）
sample_shards/       三份示例分片明细
scripts/demo_flow.py 完整操作流程演示与逐版对照
tests/               单元/接口/并发测试
```

## 接口速览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 分片、批次、明细、版本、事件 |
| GET | `/api/rank?mode&n&stores` | 即时计算（不落版本） |
| GET | `/api/version/<no>` | 某版榜单与输入范围 |
| GET | `/api/compare?before&after` | 两版对照 |
| POST | `/api/entries` | 录入销售 / 退货 / 历史更正 |
| POST | `/api/delete` | 删除明细（区分不存在 / 净额为零） |
| POST | `/api/batches` | 导入明细文件（幂等） |
| POST | `/api/publish` | 发布版本（输入不完整时 409） |
| POST | `/api/shard` | 分片暂时退出 / 恢复上线 |
| POST | `/api/seed` | 载入演示明细 |
